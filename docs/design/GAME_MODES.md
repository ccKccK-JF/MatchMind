# 游戏模式

MatchMind 只接受三种版本化 5V5 模式。Ticket 边界会规范化模式标识，恢复 Match 时再次
校验，避免未知字符串绕过评分或匹配规则。

| 模式 ID | 用途 | 匹配行为 | 正式评分 |
|---|---|---|---|
| `ranked_5v5` | 竞技排位 | 原样使用所选策略，保持最严格的初始质量目标 | Match 完成后更新 |
| `normal_5v5` | 快速普通对局 | 初始/最大评分范围 1.5 倍、评分扩展速度 2 倍、位置放宽等待减半、质量阈值降低 10 分 | 不更新 |
| `training_5v5` | 测试与模拟沙盒 | 接受完整合法评分/延迟范围，立即放宽位置且无最低质量阈值 | 不更新 |

三种模式的实时 Ticket 流程都要求十名唯一且有资格的玩家，保持开黑队伍完整，限制
每名玩家只有一个活跃 Ticket，并使用原子预占。需要合成评分、延迟、种子或批量案例
时，应使用离线批量模拟 API；它不会创建线上 Ticket，也不会修改玩家评分。

训练模式在目录中标记为可支持机器人，但第一版后端不会在真实玩家队列中静默创建
机器人。Match 保存所选算法的策略版本和模式；实时 Worker 与历史回放根据模式执行
相同的确定性策略派生，因此不依赖隐藏运行时配置。
